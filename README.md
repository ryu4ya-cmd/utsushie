# ウツシエ

日本語の一文から、声や効果音まで入った短い縦動画を作る Web アプリです。
いまは **練習モード** で動きます。外部の動画 AI や LLM は一切呼ばず、`public/samples/` のサンプル動画を返すので、お金はかかりません。

## 画面の流れ

| # | 画面 | ファイル |
|---|------|----------|
| ① | 用途を選ぶ（SNS縦型・自由。商品紹介と漫画・アニメ風は近日公開） | `src/app/page.tsx` |
| ② | 一文・雰囲気・長さ・音・字幕を選ぶ | `src/app/create/page.tsx` |
| ③ | AI が直した指示文を見て、下書き2本から選ぶ | `src/app/drafts/page.tsx` |
| ④ | 本番を生成中 | `src/app/generating/page.tsx` |
| ⑤ | 字幕の切り替え・MP4 保存・共有 | `src/app/done/page.tsx` |
| — | 作った動画の履歴 | `src/app/history/page.tsx` |
| — | 共有ページ（リンクを開いた人が見る） | `src/app/v/[id]/page.tsx` |

## 動かし方（自分のパソコンで）

Node.js 20 以上が必要です。

```bash
npm install
npm run dev
```

ブラウザで http://localhost:3000 を開きます。スマホの幅で見ると本番に近い見た目になります。

その他のコマンド:

```bash
npm test        # 指示文づくりのテスト
npm run lint    # 書き方のチェック
npm run build   # 公開用にまとめる
```

## しくみ

- **一文 → 設計図 → 指示文**：`POST /api/plan`。設計図の形と LLM への指示書は `tools/prompt-expander/system-prompt.md`。
  練習モードでは LLM を呼ばず、`src/lib/plan/mockPlanner.ts` が決まった形の設計図を作ります。
  設計図から各モデル向けの文章と字幕を作るのは `src/lib/plan/build.ts`（Python の試作 `build_prompts.py` を移したもの。テストで同じ出力になることを確かめています）。
- **モデルの選び方**：セリフ（「」）があれば Kling 3.0、なければ Veo 3.1（`src/lib/models.ts`）。
- **生成ジョブ**：`POST /api/jobs` で始め、`GET /api/jobs/:id` で進み具合を見ます。練習モードではジョブIDに開始時刻を入れ、経過時間から進み具合を計算します（サーバーに状態を持たないので Vercel の無料プランでもそのまま動きます）。
- **字幕**：セリフから WebVTT を作って動画に重ねています。MP4 への焼き込みは本番モードで FFmpeg を使う予定です。
- **履歴**：完成画面を開くと、この端末のブラウザ（localStorage）に自動で残します（最大50本、`src/lib/history.ts`）。端末をまたいで見られるようにするのはこれから。
- **共有**：「動画を送る」は端末の共有画面で MP4 を渡します（TikTok・Instagram・YouTube 向け）。X・LINE・Facebook とリンクのコピーは共有ページ `/v/:id` のアドレスを送ります（`src/lib/share.ts`）。どれも API キーやログインは要りません。練習モードではジョブIDからサンプル動画を割り出すので、サーバーに何も保存しません。
- **モード切り替え**：スイッチは環境変数 `UTSUSHIE_MODE` の1つだけ（`src/lib/mode.ts`）。何も設定しなければ練習モードです。
  `live` にすると本番モードになり、動画を本物の API に頼みます（下の「本番モード」）。

## 本番モード（動画 API につなぐ）

> ⚠️ 本番モードは **1本ごとにお金がかかります**。テストはすべて偽の通信で行っていて、本物の API はまだ一度も呼んでいません。

| | セリフあり | セリフなし |
|---|---|---|
| モデル | Kling 3.0（公式 API） | Veo 3.1（Gemini API） |
| 下書き2本 | std・5秒・音なし | Veo 3.1 Fast・8秒 |
| 本番 | pro・10秒/15秒・音あり | 8秒を作ってから「延長」でつなぐ（720p） |
| コード | `src/lib/video/kling.ts` | `src/lib/video/veo.ts` |

- つなぎ役は `src/lib/video/live.ts`。練習モードと同じくサーバーに状態を持たず、動画 API のタスクIDを **署名付きのジョブID** に入れます（作り替えたIDで勝手に生成を始められないように）。
- できた動画は `GET /api/jobs/:id/video` からサーバー経由で返します（Veo の動画は API キーがないと読めないため）。
- 必要な環境変数は `.env.example` を見てください。足りないときは API を呼ばずにエラーになります。
- 指示文の書き直し（LLM）はまだなので、本番モードでも設計図は練習モードと同じ決まった形で作ります。

**本番に切り替える前にやること**

1. 公開ドキュメントから組み立てた部分の確認（Kling 3.0 のモデル名 `kling-v3`、Veo の延長リクエストの形）。最初は1本だけ試す
2. ~~ログインと回数制限~~ → 済み（下の「ログインと回数制限」）。Supabase の設定がないと本番モードは動きません
3. ~~動画を自分の保存場所に移す~~ → 済み（Supabase Storage）
4. Veo の延長はジョブIDの受け渡しで行っていて、延長を頼んだ直後に画面を再読み込みすると二重に頼む可能性がある。保存場所（KV など）を足して防ぐ
5. 画面の「練習モード」の表示を、本番モードでは出さないようにする
6. 10秒の Veo は 8秒＋延長で約15秒になるので、FFmpeg で切りそろえる

## ログインと回数制限（Supabase 無料プラン）

Supabase の環境変数（`.env.example` の3つ）を入れると、次のようになります。入れなければ今まで通りログインなしで使えます。

- **ログイン**：メールに届く「Sign in」のリンクを開く（パスワードなし、`/login`）。Supabase で Google を有効にすれば Google でも入れます。
  リンクはページを開いたのと別のブラウザで開かれることが多い（ホーム画面アプリ、Gmail アプリ → Chrome など）ので、合言葉の要らない implicit 方式にしています。
  リンクを開いたブラウザでログインするので、ホーム画面アプリの中ではログインが続きません。数字のコードでのログインも作ってあり、独自のメール送信（SMTP）をつないで Supabase のメールの文面に `{{ .Token }}` を足し、`NEXT_PUBLIC_UTSUSHIE_EMAIL_CODE=1` にすると出ます（標準のメール送信では文面を変えられません）。
  画面は Supabase の公開キーでログインし、サーバーへ頼むときにトークンを付けます。サーバーはトークンを Supabase に確かめてから受け付けます（`src/lib/account.ts`）。
- **回数制限**：1人あたり・1日あたりの上限（既定は下書き3回・本番1回）と、全員の合計の上限（下書き30回・本番10回）。日本時間の0時に戻ります。
  数えるのは Supabase の関数 `use_generation` で、同時に頼まれても上限を超えません。回数は生成を頼む **前** に使い、動画 API の設定が足りないときは使う前に止めます（`src/lib/quota.ts`）。
- **動画の保存場所**：本番モードで完成した動画は、Supabase Storage の `videos`（公開・50MB まで）に `ユーザーID/推測できない名前.mp4` で移します。
  履歴や共有ページはそちらを指すので、動画 API 側の動画が消えても見られます。移せなかったときは今まで通りサーバー経由で返します。無料プランの保存容量は 1GB（15秒の動画で数十本〜百本ほど）。
- **本番モード**は Supabase の設定がないと動きません（URL を知っている人が誰でも生成できてしまうため）。

Supabase の表・関数・保存場所は [`supabase/schema.sql`](supabase/schema.sql) にまとめてあり、Supabase の「SQL Editor」に貼って「Run」を押すと作られます（何度実行しても大丈夫）。
どれもシークレットキーを持つサーバーからしか読み書きできません。

> メールでのログインは、Supabase の標準のメール送信を使うので **1時間に数通まで** です。一般公開の前に、Google ログインを有効にするか、メール送信サービス（Resend など、無料枠あり）を Supabase につなぎます。

bash scripts/make-samples.sh   # ffmpeg が必要

## Vercel で公開する

1. https://vercel.com に GitHub でログインし、「Add New → Project」からこのリポジトリを選ぶ
2. 設定は変えずに「Deploy」を押す（環境変数は不要）
3. `○○.vercel.app` のアドレスで見られます
